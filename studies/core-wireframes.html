A surface that
reaches back.

Octopus: one coherent messaging environment that gathers, reaches, opens and settles around human intent.

Five designsVisual directionScreens & wireframesStoryboardInteraction rules

For people moving between private conversations, shared photographs and small group plans. This is an exploratory concept, not a validated redesign or an official SimpleX roadmap. Organic form expresses interaction: each branch leads somewhere, each boundary communicates access, each fold exposes a useful action.

Five predictions, five designs.

01 / Living present

The conversation mantle

A spacious shared view gathers the current plan, open questions and objects. A persistent Messages link preserves the original conversation.

Action: tap “Saturday · proposed” to see its source and respond. A personal summary cannot mark collective agreement.

Biological analogy: coordination within one body.

02 / Local tools

The reaching arm

Touch an object or tap Tools. A short curved fan opens within thumb reach: Write, Photo, Voice. The selected action expands in place.

Action: choose Photo, review its recipient and preview, then press Send.

Biological analogy: local sensing and control in an arm.

03 / Shared image

The contact surface

A sent image becomes a place for anchored replies. Each annotation has an author and timestamp; the original image stays available.

Action: tap a location, type or record a reply, then send it to the named audience.

Biological analogy: precise contact at individual suckers.

04 / Visible privacy

The social membrane

A labelled contour encloses the content being shared and its participants. Inviting Alex creates a separate shared space with an explicit content preview.

Action: select the plan, inspect “What Alex receives”, create an invitation. Membership begins after acceptance.

Biological analogy: selective exposure. A boundary is an interface cue, not cryptography.

05 / Quiet return

The resting surface

Stable named paths remain visible while tools recede. Optional on-device catch-up links back to messages; basic navigation works without assistance.

Action: open “Maya asked a question” to go directly to its source and reply.

Biological analogy: selective response to the environment.

One material, one movement language.

Warm white, deep petrol ink, shallow folds and generous space. No mandatory eight-item menu: the anatomy supplies behaviour rather than an arbitrary number of controls. The stable lower anchor holds navigation; the active branch becomes the workspace.

Rules that make the concept credible.

AreaDesign requirement
ContinuityThe same selected object remains visible as the surface expands. Back reverses the expansion and restores position and draft.
MotionPrototype target: 220–320ms unfold; no perpetual drifting. Reduced-motion mode uses immediate state change or a short fade. Hardware shape stays an implementation constraint.
NavigationStable named destinations and a persistent All chats route. Branch order is user-controlled, never silently ranked. Search and a conventional list handle hundreds of contacts.
AccessibilityFor this web sketch, explore 44–48 CSS px controls; these are not native pt/dp guarantees. Target 4.5:1 normal-text contrast, scalable text and logical screen-reader order. Every gesture has a labelled tap alternative. These are targets, not audited compliance claims.
PrivacyAudience always named before send. A contour cannot enforce access: engineering must define membership, invitations and shared-object permissions. Recipients can retain copies.
AssistanceOptional local catch-up, with source links and explicit uncertainty. Never automatic agreement or sending. Fully usable without AI.
Reality checkSimpleX describes a network without user IDs. This concept must preserve its connection model; it does not introduce global usernames or a central social graph. Shared objects and catch-up are proposed capabilities, not claimed current features.

Design critique / next iteration

The rectangular hardware is a plausible constraint. The present weakness is that flow stops at the decoration: pill buttons, separate pages and fixed toolbars remain the dominant interaction. Future work should demonstrate one continuous transformation rather than add more curved outlines.

Remove promotional microcopy from functional screens. Keep content rectangular where this protects legibility and image detail. Reserve membrane geometry for state transitions and real audience boundaries. Distinguish invited from joined participants; do not display Alex as a member while creating his invitation. Correct inconsistent avatars in the generated storyboard; the labelled wireframes define the intended actors.

Next prototype: rest → touch Maya → expand the same branch → compose → open photo tools → preview → explicit send → anchored reply → settle. Test one-handed reach, comprehension, reduced motion, large text and 100+ chats before calling the design usable. This remains an exploratory concept with no user testing or engineering validation.
